# 阶段提示词：完成真实 Pi 接入与安全续接

继续当前仓库的 `pi-continuity`。先读取现有 SPEC、UPSTREAM_AUDIT、VALIDATION、实现与测试，再决定缺口。目标是把最小核心接到真实 Pi 调用路径，不是重写已经验证的模块。

本阶段仍采用“任务约定 + 自动工作记录 + 证据档案 + 稳定近期上下文”的方案，不扩展知识图谱或自主记忆团队。

## 必须先核对

确认已固定 Pi 版本中：
- 最终模型发送边界及其之前所有输入变换；
- 工具 preflight、执行、postprocess、结果持久化和自动下一轮的顺序；
- 哪些事件真正 await，哪些异常被记录后继续；
- 自动压缩、overflow recovery、retry 与手动 compact 是否共享路径；
- 停在完整轮次边界的方法；
- 新建/替换会话后应重新建立哪些订阅和资源；
- 用户消息、取消与 follow-up 在切换过程中如何排队。

记录实际源码位置，不凭文档标题推断。若公开 SDK 缺关键关口，选择有界补丁或包装层，并明确维护代价。

## 要实现的闭环

1. 初始化一个宿主绑定的 project/task/branch/epoch；加载 TaskContract。
2. 在实际模型调用之前形成不可变 RequestManifest，验证作用域、预算、消息配对和 critical state。
3. 对副作用工具先保存操作意图；归档工具结果后再允许依赖它的下一次调用。
4. 在安全边界保存必要工作状态；生成新的最小接续包，保留关键用户原话、仍有效的限制、未完成工作、验证记录与证据入口。
5. 按实际 SDK 正确重建活动上下文或运行。需要新 session 时重新绑定资源，不复用携带越界历史的后端线程。
6. 继续任务，保持逻辑 task 不变；将旧运行输出隔离到审计记录，不让它修改新状态。

不要从 `/compact` 命令中简单返回 cancel 就宣称接管完成；也不要在钩子里异步启动一次写入但不等待，就发布新窗口。

## 关键测试

使用真实 Pi adapter 与 fake stream/工具执行器，断言最终模型输入和实际调用次数，而不是只测试一个脱离接入层的函数。

- 连续至少两个窗口的续接：早期约束依然存在，完整原始证据可以从允许范围读取。
- critical context failure、证据写失败、预算不可满足时，下一次 provider call 为零。
- 可选笔记整理失败时，仍能保留安全旧窗口，不产生假检查点。
- 后续插件或 SDK 转换不能绕过最终 gate；无法支持的扩展组合主动拒绝或明确限制。
- 混合工具调用、取消、重试、用户在换窗时改要求，结果不乱序或重复执行。
- 旧 epoch 结果经过 await 后仍被最终提交检查拒绝。
- off 模式与未安装系统时的 Pi 行为一致；record 模式不改变请求内容。
- 活动历史大小有界，不只是出网前过滤，但内存仍永久携带全部原始历史。

没有真实 API key 时不阻塞此阶段；明确区分“真实 Pi + fake provider 测试”和“真实模型效果测试”。如果当前环境无法安装真实 Pi，交付其余测试并给出精确的待执行契约测试，不假装接入已完成。

完成后更新验收记录，给出可复现命令、实际结果与尚存边界。不要安装到全局或替换用户日常 Pi 设置。
