# Pi 任务续接引擎：Codex 提示词包

这套提示词采用最后收敛的方案：**可靠任务续接优先，复杂长期记忆其次**。它基于 Pi，但不以自研 COW 文件系统、知识图谱或彻底禁止摘要为目标。

## 使用顺序

在准备开发的仓库中打开 Codex，先发送 `00_MASTER_PROMPT.md`。它要求先检查实际 Pi 版本和调用路径，然后实现一个可测试的最小闭环，而不是只生成架构文档。

完成后按顺序发送 `01_PI_INTEGRATION.md` 和 `02_RECOVERY_AND_UI.md`。每一步都检查代码与测试的真实状态；已完成且有证据的部分不需要重写。

核心功能完成后，在一个新的审查会话中发送 `03_INDEPENDENT_AUDIT.md`，避免审查只是重复实现者的解释。修复后发送 `04_EVALUATION.md`。评测前不宣称新机制优于原生 Pi。

`05_CONTINUE.md` 是长任务换会话时的续做提示，不是额外开发阶段。

**不要把所有阶段一次性并行交给多个会修改同一工作区的 Agent。**第一版按阶段串行推进。审查会话可以只读。

## 最小交付边界

第一版必须具备：任务约定、证据归档、带版本的工作记录、受控上下文组装、安全交接、运行代际隔离、明确边界的检查点续接，以及能查看实际状态的 Pi 界面。

第一版不需要：向量数据库、知识图谱、自治记忆整理团队、跨 Agent 平台兼容、自动语义合并、全文件系统回滚、生产部署或云同步。

默认关闭行为改写；使用隔离配置启用测试。没有真实模型凭据也必须完成离线行为测试。真实模型评测缺失时，要明确说明，不能用 mock 测试代替质量结论。

## 两个关键区分

- **任务续接**：保留有效要求、成果和证据，使新窗口能继续工作。
- **历史重现**：限制到旧检查点可见的内容，不能自动带入后来才知道的信息。

实际返工可以显式导入选定的失败经验；严格历史分支不能偷偷导入。两者都不回滚当前权限、删除约束或外部操作审计记录。

## 一句话启动

将总提示词粘给 Codex，或者把完整合集作为附件后发送：

> 阅读附件中的总提示词，把它转成当前仓库的实施规格。先核对实际 Pi SDK 与调用链，再直接实现第一个可运行、可测试的闭环。不要只写计划，不要发明不存在的接口，不要提前开发复杂记忆平台。完成后给出修改、实际测试结果、尚未验证的边界和下一阶段入口。
