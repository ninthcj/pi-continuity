# 换会话后的续做提示词

继续当前仓库的 `pi-continuity`。不要依赖上一会话的口头总结，先检查：

1. 仓库开发约定、未提交修改、当前分支和实际依赖版本。
2. `docs/continuity/SPEC.md`、`UPSTREAM_AUDIT.md`、`VALIDATION.md` 或项目实际采用的等价文件。
3. 当前实现、测试、已知失败和最近改动。

目标仍然是基于原版 Pi 的可靠任务续接：任务约定、自动工作记录、证据可查、有界上下文、安全换窗和明确恢复边界。不要扩大成复杂长期记忆平台。

确认哪些验收项已经有真实测试覆盖，哪些只是文档中写了。选择下一项最小但关键的缺口继续实现；先补失败测试，再做有界修改。不要重写已通过验证的部分，不覆盖用户的其他工作。

普通技术选择按现有规格处理；只有确实缺少不可替代输入才提出阻塞。没有真实模型凭据不妨碍离线核心与接入测试。

结束时报告实际改动、已运行命令与结果、未验证边界和精确的下一步入口。不把文档中的计划写成已完成。
