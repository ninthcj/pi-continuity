# 独立审计提示词：主动寻找续接引擎的失败路径

你现在是独立审查者，不是实现者。审查当前仓库的 `pi-continuity`，不要因为已有文档声称“有 gate / 有 epoch / 有快照”就接受其保证。

先读取规格、实际上游版本、代码与现有测试；然后追踪真实的模型请求、工具执行、SQLite 提交、附件保存和会话重建路径。第一轮以审计和最小复现测试为主，不做大重构。

## 重点攻击面

1. 扩展抛错被吞掉，下一次 provider request 仍发生。
2. gate 检查后存在另一条变换、重试或工具路径绕过它。
3. 旧 epoch 在等待 I/O 时失效，但结果仍提交到新状态。
4. 用户新要求在换窗时丢失、重复消费，或旧约束仍授权下一次变更。
5. SQLite 已提交但响应丢失；恢复逻辑重复执行同一项修改。
6. 副作用已发生，但结果归档失败；系统误当失败重试。
7. blob 未完整保存就发布引用；WAL/backup 处理丢失已提交状态。
8. inspect 会意外修改当前 ref；correct 会原地改变旧快照内容。
9. 搜索经过分支过滤，但直接 ID 读取、缓存、文件工具或其他后端线程泄露未来信息。
10. 工作区变化后旧测试仍显示有效；Git HEAD 未变掩盖 dirty/untracked 改动。
11. 分页、裁剪或消息重建破坏工具调用配对、图片或提供方签名规则。
12. UI 确认后状态已变化，操作没有再次版本校验。
13. 模型能把 proposed 写成 confirmed，或把笔记作为授权来源。
14. 可选经验整理或索引故障使安全任务无必要地全局停机。
15. 全局活动消息、索引查询、manifest 输出随历史无限增长。
16. 凭据或不允许保存的内容进入日志、备份、错误信息或测试快照。

区分三种发现：
- 可复现的当前缺陷；
- 有具体调用链支持但尚未触发的风险；
- 设计已声明且目前接受的边界。

不要把所有理论风险写成已确认漏洞，也不要因为测试全绿就断言安全。不要将同一模型生成的便条当作独立事实来源。

对高风险问题尽量添加最小失败测试：要断言实际 provider/tool call 次数、数据库内容、scope、epoch 或状态机，不只断言错误日志。

输出按严重程度组织的发现，包含文件/符号位置、触发条件、影响、复现或未复现说明、修复建议及对应测试。也检查文档是否宣称了实现没有提供的保证。

最后给出阻止启用 active 模式的问题，以及仅影响可选体验的问题。没有发现可复现问题时，说明实际覆盖范围和残余风险；不要写“没有 bug”。

收到修复指令后，逐项最小修复并跑回归，不删除失败测试、不放松断言来换取通过。
